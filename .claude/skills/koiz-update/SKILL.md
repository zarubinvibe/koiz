# Обновление Койза

Обновление показывает изменения до того, как что-то тронет, и отказывается оставить установку в половинчатом состоянии.

## Порядок

1. Убедиться, что рабочее дерево чистое:

   ```bash
   git -C <папка koiz> status --short
   ```

   Есть незакоммиченные правки — остановиться и сказать об этом владельцу. Обновление поверх чужой работы стирает ее молча.

2. Показать, что придет:

   ```bash
   git -C <папка koiz> fetch origin
   git -C <папка koiz> log --oneline HEAD..origin/main
   ```

   Пустой список означает, что копия уже свежая, и дальше идти незачем.

3. Потянуть только fast-forward:

   ```bash
   git -C <папка koiz> pull --ff-only origin main
   ```

   Отказ команды означает разошедшуюся историю. Разбирать это руками вместе с владельцем, а не разрешать слияние молча.

4. Проверить прибор после обновления:

   ```bash
   node <папка koiz>/scripts/koiz.mjs --selftest
   node <папка koiz>/scripts/koiz-mutate.mjs
   ```

   Красный селфтест после обновления — повод откатиться на прежний коммит и завести issue, а не повод работать дальше.

## Что обновление не трогает

- Журнал уроков `~/.claude/koiz/lessons.jsonl`. Он живет вне репозитория, и `git pull` до него не дотягивается.
- Ваши настройки `~/.claude/settings.json`. Запись хука уже стоит и переписывать ее не нужно; повторный `install.sh` увидит ее и оставит как есть.
- Каталог базы, если вы выбрали не путь по умолчанию.

## Если обновление сломалось на середине

Вернуться на прежний коммит и сказать об этом прямо:

```bash
git -C <папка koiz> reset --hard <прежний коммит>
node <папка koiz>/scripts/koiz.mjs --selftest
```

Половинчатая установка хуже старой версии: она выглядит рабочей и падает в неожиданном месте.
