Спасибо, что заглянули. Проект намеренно маленький: три файла на голом Node, без зависимостей и без сборки. Это ограничение, которое обязана уважать любая правка.

## Путь

Сделайте fork, заведите ветку, оформите commit, отправьте push и откройте Pull Request. Прямой push в `main` отклонит релизный gate.

## Перед тем как открыть Pull Request

Прогоните все три проверки. Они быстрые, и они и есть весь контракт ревью:

```bash
node scripts/koiz.mjs --selftest     # логика прибора
node scripts/koiz-mutate.mjs         # 19 сломанных правил, каждое обязано быть поймано
bash scripts/koiz-acceptance.sh      # приемка целиком, десять пунктов
```

Красная приемка означает, что правка не готова. Зеленая приемка при неизмененном селфтесте после новой логики означает, что селфтест эту логику не покрывает, и правильный ответ такой: дописать мутацию, а не порадоваться.

## Новая логика приходит со своей мутацией

`scripts/koiz-mutate.mjs` ломает по одному правилу и требует, чтобы селфтест это заметил. Добавили ветку, добавьте мутацию, которая ее ломает. Правило, которое нельзя сломать нарочно, никто не проверяет.

## Стиль

Комментарий объясняет причину, а не пересказывает строку. Замер в комментарии идет со своим числом. Функции короткие, вложенность мелкая, ранний возврат вместо лестницы условий. Русский в прозе и комментариях, английский в командах CLI и именах API.

## Что будет отклонено

Зависимость. Шаг сборки. Переделка формата журнала, которая ломает чтение старых записей. Правка, после которой прибор ходит в сеть. Это не вкусовщина: каждая такая правка убирает свойство, ради которого проект существует.

## Шрифт резьбы

Подписи на схеме такта режет `podpisi_takta.py` шрифтом Cormorant (лицензия SIL Open Font License). Шрифт сюда не кладется; если нужно пересобрать схему, поставьте его с https://fonts.google.com/specimen/Cormorant в `~/Library/Fonts`.
