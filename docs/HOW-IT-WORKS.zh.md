# Koiz 是怎么工作的

<p align="center"><img src="assets/pantheon/doc-how-it-works.png" alt="大理石桌上并排放着四样东西：一摞薄薄的大理石片、被金色别针穿透的摊开册页、一片更厚的石片，以及开着长方形通孔的石板" width="100%"></p>

三件事被有意分开：正是把它们混在一起，教训库才会烂掉。

## 采集便宜、确定，而且只由机器做

会话结束时，`SessionEnd` 钩子把本来就在你磁盘上的会话记录交给仪器。仪器从里面读磁盘能证明的东西：失败的命令、退出码、被拒的闸门、一个任务重试了几次。

有两类噪音进不了库。守卫正常工作不算失败，所以已经拦住的阻断会被跳过。短于三个实义词的证据也会被跳过：用碎片拼出来的、没有固定的教训，之后会无缘无故拦下夜里的活儿。

采集是幂等的。同一份记录读两遍不会写出两条：每个候选都带指纹，重复只会让计数加一，而不是多出一行。

## 存储只追加

`~/.claude/koiz/lessons.jsonl` 这份日志只做追加。库的状态是从头重放日志得到的结果，所以每条记录都留着自己的历史，也不会被悄悄改掉。

一条记录包含：什么坏了、怎么复现、为什么会这样、被什么关掉了、项目、日期和生效区间。不再适用的教训按日期关闭，而不是删除。它不是假话，只是不再成立了，关闭的原因就写在旁边。

库有预算，默认三百条生效教训。上限本身就是意义所在：没有上限，库会一直长下去，也就没人真的去归并。

## 归并是单独的、有意识的一趟

写入时顺手合并既贵又会丢数据，所以它被拆成了自己的命令。`collapse` 找出形状相同的教训，提出一条能覆盖它们的规则，并把要合并哪几条摊开给你看。`collapse --dry` 只给建议，什么都不改。

## 固定，是工具和日记的分界

每条记录都有固定这一栏，只有五个合法值：`hook`、`deny`、仪器、测试，或者「没有」。自造的值会被拒绝。没有指向具体文件或命令的固定也会被拒绝：打不开的机制不算机制。

「没有」是合法的，也是诚实的。它说明机制还不存在。

## 闸门把库变成压力

`node scripts/koiz.mjs gate` 在教训回来、而固定栏还写着「没有」时以非零码退出。把它写进夜间脚本或推送前的钩子，库就开始拿你自己的结论管着你。诚实的出路有两条：用机制关掉这次重复，或者承认这条规则不成立，按日期关掉它。要延期就得写上日期和理由。

## 一份库，所有项目

检索键是错误的类别，不是仓库的名字。你在做移动应用时采到的教训，从法律业务那个项目里也能找出来：坏掉的是路径处理，不是那个应用。

所以日志才放在所有项目目录之外。放在某一个仓库里的库，只会提醒已经站在那个仓库里的人，而那恰恰是最不需要这条教训的地方。

## 装了之后系统里多了什么

只有两样：`~/.claude/koiz` 这个目录，以及设置文件里一条 `SessionEnd` 记录。没有守护进程，没有开机启动项，没有后台任务，也没有任何网络连接。要卸载，把那条记录删掉就行，日志留着还是你的。

## 为什么自检值得信

`scripts/koiz-mutate.mjs` 每次打断仪器的一条规则，一共十九条，并要求自检每一次都失败。有变异活下来，就说明那个检查根本没在检查。这道闸门第一次跑，就抓到了一个真实缺陷：仪器在符号链接路径上是以 0 退出的，而不是拒绝。
