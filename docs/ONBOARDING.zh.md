# 上手引导：第一次运行，一步一步来

<p align="center"><img src="assets/pantheon/doc-onboarding.png" alt="科俄斯站在大理石桌后面，掌上摊着那本大理石册页，蓝色路径从画面左边一直连过来" width="100%"></p>

这一页写给从来没有从 GitHub 装过工具的人。每一步都写清楚要敲什么、敲完屏幕上会出现什么。如果某一步出来的是别的东西，就停在那里开一个 issue：会骗人的引导比没有引导更糟。

需要 Git、Node 20 或更新的版本，以及一个终端。不需要任何智能体。

1. **检查 Node。** 敲 `node --version`。应该看到类似 `v22.14.0` 的东西。如果版本是 `v18` 或更低，先去 https://nodejs.org 装一个新版再回来。

2. **选一个目录，把项目克隆下来。** 敲 `git clone https://github.com/zarubinvibe/koiz.git`，然后 `cd koiz`。Git 会打印几行关于清点和解包对象的信息，之后你就在一个包含 `scripts`、`docs` 和 `install.sh` 的目录里了。

3. **运行安装。** 敲 `bash install.sh`。它只问一个问题：要不要把教训采集挂到会话结束上。回答 `y`。它会打印教训库的路径、一行 `хук вписан` 加上你的设置文件路径，然后跑一遍自检。

4. **读那行自检结果。** 最后一段以 `selftest ok` 开头，并列出检查了哪些内容。如果不是这样，说明安装没有走完，这一页后面的东西都不会正常。

5. **向空的库提个问题。** 敲 `node scripts/koiz.mjs ask "什么地方坏过"`。刚装好时库是空的，所以它回答什么也没找到。这是正确答案：它证明仪器能读自己的日志。

6. **手写第一条教训。** 敲这一条命令：

   ```bash
   node scripts/koiz.mjs add --what "脚本顺着符号链接走，把启动器覆盖了" \
     --why "路径是凭信任拿来的，没有看它到底指向哪里" \
     --pin тест --pin-ref scripts/koiz-mutate.mjs
   ```

   仪器会打印新记录的标识。`--pin` 这一栏就是整个项目的意义所在：没有机制的教训只是抱怨。

7. **换一个项目再找它。** 离开这个目录，进入你另外任何一个项目，用你教训里的某个词再跑一次 `ask`。库是所有项目共用的，所以在那边也能得到答案。

8. **看看欠账。** 敲 `node scripts/koiz.mjs debt`。它会列出那些又回来了、却还没有任何机制拦着的教训。刚建好的库里这个列表是空的，这正是你想看到的。

9. **把闸门放到会疼的地方。** 敲 `node scripts/koiz.mjs gate`。没有欠账时它以 0 退出，有没固定的重复时以非零码退出。把这一行加进你的夜间脚本或推送前的钩子，库就开始拿你自己的结论管着你。

10. **结束会话，让机器干活。** 正常退出你的智能体会话。会话关闭时，钩子会读取记录并自己写好草稿。打开 `~/.claude/koiz/capture.log` 就能看到它采到了什么。

## 怎么更新

以后要拿最新版本，在 Claude Code 里说 `/koiz-update`。它会先把改了什么摊给你看，只做 fast-forward 拉取，不碰你的日志和设置，更新完再跑一遍自检。不用智能体的话，在这个目录里 `git pull --ff-only` 是一样的效果。

## 如果它有用

给 Koiz 点亮星标：https://github.com/zarubinvibe/koiz。这只要一秒，却决定别人能不能找到这个项目。

想改点什么？流程很短：先 fork 仓库，建一个分支，提交 commit，推送 push，然后开一个 Pull Request。请不要直接向 `main` 推送，发布闸门会拒绝。
