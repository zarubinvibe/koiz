# 对话式上手：智能体和你一起安装 Koiz

这一页写给刚打开一个新克隆、需要向人解释自己的智能体。从上往下读，一步一步来，每一步都说清楚你在做什么、为什么这么做。

<!-- owner-greeting:start -->

> 你好。我是 Koiz，蜂群的审问者。
>
> 我为你所有的项目保存同一份教训库。教训进来的方式是拆解，不是复述：什么坏了，为什么会这样，重复被什么关掉了。最后一栏最重要，它写着「没有」，这条教训就还没做完。
>
> 我们现在把我装到你的机器上。我一次只问一个问题，每一步之前先说磁盘上会改变什么，没有你的「好」我什么都不做。

<!-- owner-greeting:end -->

## 第 1 步：先看清楚我们站在哪里

**我在做什么：** 检查 Node 版本，确认我们在 Koiz 的克隆目录里。

**为什么：** 在低于 20 的 Node 上安装，会在三步之后抛出一个看不懂的错误，那时候你面对的是一个装了一半的东西，比现在难处理得多。

**磁盘上会改变什么：** 什么都不变，这一步只读。

**你会得到：** 一个诚实的答案：下面这些到底能不能跑。

```bash
node --version
ls scripts/koiz.mjs
```

## 第 2 步：决定教训库放在哪里

**我在做什么：** 问你是保持默认的 `~/.claude/koiz/lessons.jsonl`，还是换个地方。

**为什么：** 教训库放在仓库之外，因为教训里带着路径和别人项目的名字。如果你的工作文件在加密卷或共享磁盘上，现在选好比以后搬日志便宜得多。

**磁盘上会改变什么：** 暂时什么都不变，我只是记住你的回答。

**你会得到：** 一个固定的位置，以后总能在那里找到你的教训。

**岔路：** 用默认位置，或者给出你自己的目录并通过 `KOIZ_DB` 传进来。

## 第 3 步：把采集挂到会话结束上

**我在做什么：** 运行 `bash install.sh`，和你一起回答它的那一个问题。

**为什么：** 这是我在自己目录之外做的唯一改动，它让你不用再手打教训。手打这件事，人一般坚持两天。

**磁盘上会改变什么：** 出现教训库目录，`~/.claude/settings.json` 里多一条 `SessionEnd` 记录；原来的设置文件会在旁边留一份副本。

**你会得到：** 会话结束时自己写下来的教训。

**岔路：** 现在就装钩子，或者跳过它，用 `add` 命令手动记录。

```bash
bash install.sh
```

## 第 4 步：如果有旧教训，就搬过来

**我在做什么：** 问你手里是不是已经有一份写着结论的文件，然后整份迁移过来。

**为什么：** 旧教训进到空库里是历史。进到已经有内容的库里，它们会和新的混在一起，之后没有任何办法把它们分开。

**磁盘上会改变什么：** 日志里追加记录；已有的记录一条都不改。

**你会得到：** 迁移了多少条、丢了多少条，而后者必须是零。

```bash
node scripts/koiz.mjs migrate --file ~/.claude/self-learning/lessons.md
```

## 第 5 步：写下第一条教训，并把闸门装上

**我在做什么：** 问你最近一周什么地方坏过，和你一起写下来，然后把欠账闸门演示一遍。

**为什么：** 玩具例子证明不了任何事。第一条教训必须是你自己的，否则这个库始终是别人的。

**磁盘上会改变什么：** 日志里多出你的那条记录。

**你会得到：** 一个活的库，以及一条在没固定的教训再次出现时会变红的命令。

```bash
node scripts/koiz.mjs add --what "什么坏了" --why "为什么会这样" --pin test --pin-ref scripts/koiz-mutate.mjs
node scripts/koiz.mjs debt
node scripts/koiz.mjs gate
```
